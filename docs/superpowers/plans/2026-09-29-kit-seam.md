# The kit seam: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A kit is declared in one place (`KitDecl`), fails in one way
(`KitError`/`ContractError`, enforced at `KitSet.get`), and is checked at
launch by one function (`contract.launch_problems`) that both runners call.

**Architecture:** `KitDecl` gains the facts now spread over adapter class
attributes, plus a factory string, so `contract.ADAPTERS` and its lazy
registration go. `KitSet.get` returns each kit wrapped in a guard that
turns expected Python failures into `KitError`. `launch_problems` replaces
`graph/run.py:launch_refusals`, `contract.check_kits` and
`contract.config_name_problems`, and `start()` joins the Kit interface.

**Tech Stack:** Python 3.12 (ana 2.8.0 via `$AUTORESEARCH_PYTHON`),
stdlib `unittest`, LangGraph (unchanged).

**Spec:** `docs/superpowers/specs/2026-09-29-kit-seam-design.md`

## Review Focus

1. **A `KitToolError` or `ContractError` passes through the guard as the
   same object**, so `call_with_retries` and existing handlers still see
   their type. Pinned in Task 2 (`test_contract_and_tool_errors_pass_through_unchanged`).
2. **An optional attribute read through the guard** (`getattr(kit,
   "step_problems", None)` on a kit without the hook) returns the default,
   not an error. Pinned in Task 2 (`test_a_missing_optional_hook_reads_as_none`).
3. **Flat versus package import.** In flat mode (`graph/run.py`), a factory
   must load `adapters.prodtools`, not `core.adapters.prodtools`, or a
   second copy of `contract` appears and the runners stop catching its
   `ContractError`. Pinned in Task 1 (`test_a_flat_import_loads_the_flat_adapter`).
4. **The launch check's KitSet is closed** when `graph.closed_loop`
   refuses, so no kit server outlives the refusal. Pinned in Task 3
   (`test_the_launch_check_kits_are_closed_on_refusal`).
5. **A static refusal starts no kit.** A bad executor, a missing ticket or
   a bad config name refuses before any kit is opened. Pinned in Task 3
   (`test_a_static_problem_opens_no_kit`).

## Rulings made while planning

- **Factory strings name the module relative to `core/`**:
  `"adapters.prodtools:ProdtoolsKit"`, not the spec's
  `"core.adapters.prodtools:ProdtoolsKit"`. `contract.load_factory`
  prefixes `core.` when `contract` itself was imported as `core.contract`.
  A fixed `core.` prefix would load a second copy of `contract` under
  `graph/run.py`'s flat imports. The spec's intent (a string on the
  declaration, imported when the kit opens) is unchanged.
- **Catch sites that also wrap engine code are split, not widened.**
  `scheduler._run_one` and `study_graph.node_preflight` get one `try`
  around engine-side work (keeping its `KeyError`/`ValueError`, and
  `OSError` in `node_preflight`) and one around kit calls catching
  `(KitError, ContractError)`.
- **Static checks first.** `launch_problems` collects executor, Kerberos
  and config-name problems, and returns them without opening a kit if
  there are any. The executor problems alone skip the Kerberos check (as
  `launch_refusals` does today).
- **`graph.run` checks `broken.txt` before the launch check**, so an
  already-broken point is refused without starting a kit server.
- **Adapter rewraps.** Kept, with corrected comments: `anakit._git` (names
  the git command), `prodtools._prepare` staging (names the destination and
  the count), `offline_preflight.check` (names the workdir and cache).
  Deleted, because the guard now does their only job and the bare
  `OSError` already names the path: anakit's step-directory rewrap, its
  result-file write rewrap and its `_record` read rewrap.
- **Acceptance (Task 5) runs in the controller session**, not a subagent:
  it needs the kit checkouts, the sandbox and a 10-minute local run.
